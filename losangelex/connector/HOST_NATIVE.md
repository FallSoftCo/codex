# Host Globals and shared native transport

An enrolled host Global joins rooms through ordinary Hollywood membership. A room
adds no native process. Hollywood transports authored messages; native Codex owns
its thread, tools, model turns and cancellation. The host daemon is Codex's Unix
WebSocket server itself, not another model or execution broker.

The first deployed scope is the existing OZZZ CPU and GPU Globals. Older workers
retain their original owners/services until explicitly retired or migrated. This
is not a claim of complete fleet enrollment or room-owner database failover.

## Ownership and migration

The protected `lax-native-host/v1` manifest binds authority, host, owner agent,
service UID, native package, account profile, state, workspace and private socket.
The current socket is private to that service UID. Additional local consumers
must share that approved trust/profile boundary; separate account profiles are
not implicitly merged.

Private-to-shared adoption retains the existing CODEX_HOME, SQLite/log location,
thread identity, receive journals and original instruction overrides. It requires
an explicit original configuration digest and context identity, old owner drainage,
and a real metadata-only native read. It does not call thread/start or turn/start.
A stopped daemon is not resurrected by installation reconciliation.

Transport-only upgrades of an already conversational agent may preserve historical
unknown delivery records without altering any journal bytes or replaying work.
They still require disabled legacy placement, the exact unchanged canonical unknown,
no old executor, and the original context present/idle. Claimed-execution upgrades
keep the strict unresolved-journal prohibition. Unknown business effects are not
converted into successful results by moving a transport.

## Tools and reconnects

The connector supplies its exact reviewed tool declarations on every resume.
Creation-time tools on old threads are not authoritative for a later connector.
The qualified native engine permits identical loaded bindings and rejects changed
bindings on a loaded context. A reviewed tool upgrade therefore uses a cold idle
boundary; it does not patch SQLite or alias incompatible old tool names.

Cold migration qualification retains real native history and exercises a new
reviewed callback after replacing legacy declarations. It also checks identical
loaded reattachment, with an isolated local provider and no account model calls.
Real room requests separately verify actual account execution and publication.

## Release integrity

Immutable software receipts remain unchanged. Only Python cache additions that
reproduce exactly from sealed source with the running interpreter may be accepted
as derived files. Missing files, changed source, arbitrary additions and altered
bytecode remain errors. Software activation uses the existing enrollment/config/
unit compare-and-swap workflow and records component identities and rollback files.

Room-default registration is explicit per authority/node and preserves existing
membership revocations. Historical messages use their send-time recipients, so
new membership does not replay old requests. Normal peer observations add context
without inference; directly addressed peer requests retain agent authorship.

## Darwin package and initial ownership handoff

macOS uses the canonical package builder and its pinned Codex V8 artifact pair, retaining the V8 sandbox, code-mode host and ripgrep. The package is qualified as the actual service UID before execution. A shared transport handshake alone does not qualify tool execution.

A new persistent Global is named through native `thread/name/set` before releasing its initialization connection. Native naming materializes the original empty context; a metadata-only `thread/resume` confirms handoff without a dummy model turn, replacement context or storage edits. Installation validates the typed room subscriptions before launching their owner. launchd owns the Mac services; systemd enrollment is not claimed for macOS.


SDK228 records exact native turn acknowledgements for room inputs. Final native answers to human inputs or explicit peer requests are delivered asynchronously through the original Hollywood publication ledger, with source and audience preserved. Explicit accepted final publications suppress fallback. Passive context never changes reply scope. Ambiguous multi-room/private scope is retained locally for explicit publication rather than guessed. Lost HTTP acceptance is reconciled by original command identity, never resubmitted. No model polling or per-room native process is introduced.


SDK229 adds an explicit paired shared-native release: `sharedNativeUpgrade` pins the original native manifest and unit digests. Preparation validates the actual old daemon, original thread and complete new package while services remain untouched. The operator must drain and stop both original participant and shared daemon before approval; publication then updates the same participant config/unit, host manifest/native unit and enrollment in one retained prefix-CAS operation. Reconciliation preserves the original operation after partial metadata publication. The operator starts each existing service once afterward, resumes the original context and renews registration/restart approval. No deployment function starts inference or replays input. Other loaded native contexts require coordinated drainage rather than automatic migration.

SDK230 retains the original two top-level release targets for deployed reader compatibility. Additional shared-native targets are an additive nested `sharedNativeUpgrade.targets` extension; the latest writer verifies the combined five-stage prefix and only publishes acceptance after both native targets and original enrollment are committed. Old observers continue to see the valid original three-stage receipt. SDK229 paired preparations with expanded top-level targets must not be activated on older observers.


Reply routing resolves only inputs that actually expect an answer (human input, explicit peer request, or expectsReply). Passive context cannot replace that source or make its audience ambiguous; multiple real requests across audiences still require deliberate publication. Reply eligibility is indexed and existing adapter receipts are backfilled in bounded batches. No model history scan is involved.

A confirmed historical passive-source suppression can be recovered for one exact native item and original source with `python -m lax_connector.repair_room_output --config ORIGINAL_CONFIG --item ORIGINAL_ITEM --source-event ORIGINAL_REQUEST`. Run as the original connector UID while its connector is quiesced: the command requires its existing connector.lock. It retains an append-only recovery audit and only queues the original body for the ordinary durable publication ledger. It does not connect/start a native turn or service, sweep old outputs, replay unknown sends, widen an audience or re-enable workers. Ordinary peer-only answers remain suppressed, and accepted/explicitly superseded outputs are never reopened.


A connector-only release may explicitly set retainNativeImage=true. Its old/new binary path stays exactly unchanged and bound to the canonical shared host manifest, original native process incarnation and complete accepted package. Only the new interpreter/SDK has a new immutable software root. Preparation qualifies the actual service-UID interpreter and retained package; every transition step rechecks the protected native declaration, service, image and helper identities. This mode cannot change engine bindings or combine with a native-engine upgrade/adoption. Read-only native state changes remain valid; image/package changes require fresh review.

Stage connector software with independent copies. Do not hardlink the live native image or SDK tree merely to satisfy release layout: link-count changes alter ctime and can invalidate existing restart pins before activation. The retained dependency path removes that requirement and supports future SDK releases whose original binary is already outside the connector closure. Keep the retained native package available; a connector release does not retire it. Existing readers can observe ordinary config/unit/enrollment fields; owning mutation uses the qualified updated writer and its retained dependency checks.

SDK235 treats byte-identical metadata targets as neutral when validating a release prefix. Reconciliation still requires every changed target to form an established prefix and rejects uncertain bytes or an enrollment ahead of unapplied changed targets. This permits connector-only upgrades whose configuration is intentionally unchanged without replaying an original operation.

SDK236 disables bytecode writes in the root-side room factory installer. The release verifier accepts a newly created protected __pycache__ directory only if every new child is bytecode reproduced from sealed original source; empty directories, unexpected content, writable directories and changed source remain rejected. Only proved parent-directory size/timestamps may differ; inode, owner and permissions remain pinned.
