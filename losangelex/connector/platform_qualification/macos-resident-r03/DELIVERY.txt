Input and parent policy mapping
The protected common spec uses the supplied r03 fields. parentRuntime is:
 {agentId: original host-owner agent UUID,
  roomOriginPolicy: {path: protected approved host account policy, sha256: rawSHA},
  identity: {pid,uid,birth,image} fresh existing parent-process identity}
The inner macOS policy is schema lax-macos-room-account/v1; root/owner prepares it ONCE at deployment, not the adapter. Never synthesize this authority from an ordinary config flag. Fields:
 uid,user,serviceHome — exact NSS/effective account; HOME/profile remain original.
 authorityId,hostId,ownerAgentId — original enrolled native-host owner.
 initialPermissions — explicit {sandbox:danger-full-access,approvalPolicy:never}.
 nativeManifest,parentConfig,ownerReceipt — each exact protected {path,sha256}.
 Parent config retains its original agentId/nativeThreadId/nativeServer/profile.
 Enrollment binds agentId,nodeId,nativeThreadId,sharedNativeService. Neither
 secret config contents nor profile/auth contents are returned or copied.
 agentRoot — preexisting owner-private root, disjoint from original profile and
 native/Global state/workspace. agentRootIdentity has device/inode/uid/mode/type.
 Per-operation nativeIdentity and parentRuntime.identity — exact {pid,uid,birth,
 image}. These are fresh process evidence, not permanent PIDs baked into the
 account policy. birth is Darwin kernel seconds.microseconds (proc_bsdinfo);
 image is proc_pidpath. Use module.process_identity(pid) IN PROCESS to construct
 them. It double-checks PID/UID/kernel birth around image lookup and rejects
 stopped/zombie processes. Existing accepted ps-date evidence was independently
 mapped to the same kernel start during qualification. PID alone never suffices.
 Optional nativeProcess/parentProcess policy fields are accepted as fallback
 qualification witnesses; production can omit them and provide fresh operation
 pins. A static account/root authorization need not be reissued on each reboot.
 interpreter,binary — {path,sha256} original approved interpreter/native image.
 nativeSocketPin — accepted lax-native-ipc-alias/v1 witness if original socket
 is a symlink; only that exact alias/target/private parent under root-sticky
 /private/tmp is admitted. All other private-path ancestry checks stay strict.

Public nativeIdentity must match the original actual native for this operation,
and nativeHostManifestSha256 must equal policy.nativeManifest.sha256. Fresh

New operations can use a freshly accepted parent incarnation with the unchanged

Parent upgrade or policy/credential rotation still needs owning transition and

Unknown/recovery semantics
Before initialization a durable native-initialization-intent is saved. Existing
SDK246 room_bootstrap handles canonical binding/request digest/name/settings.
Prior ready is read/reconciled without another native start. Only positively
proven connecting/transport-unavailable with threadStartAttempted=false may
resume the SAME operation through that initializer. Exact prior context bytes
are retained as unstarted-before-SHA.json before doing so. Creating/created/
naming or any uncertain thread/start remains unknown, unchanged and un-replayed.
Absent evidence is not proof of non-dispatch. No recovery approval is invented.
Initial full policy is verified from the accepted bootstrap receipt. Later owner
restrictions are not reset by ordinary inspection or resume.
