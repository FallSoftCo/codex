# Resident parent acceptance successor

This source successor keeps qualified07d1 / immutable SDK247 unchanged. Release
version and complete wheel are assigned by the owning release coordinator.

The opt-in Windows v2 platform adapter binds a fixed private owner acceptance
locator back to the immutable policy SHA and actual process/native incarnation.
V1 stays hash-pinned. Startup emits only CLOSED evidence; it cannot approve itself.
The common host policy consumes the same platform reader and rechecks open state
and identities, then fences factory admission to actual resident PID and argv.
Read-only release inspection verifies the accepted parent, not its inspecting CLI.

The existing catalog/reconnect edge inspects only parent-deferred registrations
that have never attached in this parent incarnation. A changed validated owner
record permits immediate full validation. An unchanged known-unstarted prerequisite
has bounded event-edge backoff (25..300s), with no timer/model turn. Original agent,
config, room and native-thread bindings are checked before attach. There is no
thread/start, per-agent process/service, running-sibling relabel, failed/stopped
resurrection or historical input replay. A closure during restoration leaves the
remaining original never-attached records parent-deferred.

The owner must retain the original operation and independently validate admission,
manager/argv/native identity and aggregate native+I/O+control quiet. No operation
string, startup descriptor or this source fixture confers authority. Existing
unknown thread/start or publication receipts remain held, never replaced/replayed.

CPU tests use real private files and real supervisor/control methods, with mocked
process/native/session facts. The separate BLD fixture uses real Windows private
ACL checks but synthetic process identities. Neither claims real Windows activation
or a child model/tool turn. Root owns the latter once on CPU after actual activation.
