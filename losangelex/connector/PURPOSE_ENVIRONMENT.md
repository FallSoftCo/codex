# Purpose-native installation environment

LAX installs approved environment routes as part of its existing purpose-agent installation. No new daemon, model, worker wakeup or communication intermediary is involved.

The authority profile remains the existing root-owned environment.json contract. It declares exact host/repository references, SSH argv routes, a GitHub provider account and build-owner/capacity-guard routes. Metadata is not a permission grant or proof that a dependency works. Root setup binds approved provider metadata to the installation and actual NSS identities, creates root-owned gh/ssh clients, and records their hashes. Existing installations reconcile the same record; changed profiles or unreceipted clients require explicit inspection.

Each purpose runner activates only its own process environment before starting its native app-server. Scoped GitHub credential helper and GitHub SSH-URL rewrites allow ordinary Git commands to use the approved provider. Credentials remain with the provider account; gh receives a transient child-process token, never a persisted worker credential or model prompt. Existing per-agent GitHub authorization is retained. SSH routes use the already authorized account/key and preserve ordinary OpenSSH for other calls.

The installer and launcher share purpose_environment. Actual identity comes from NSS, not role labels or incoming messages. A renamed role does not change the authority/account. Contexts and working directories do not change when an agent reads another room. Source references identify a host and ownership: a coordinator-owned checkout may require authorized sudo for reads and is not a shared writable checkout. Agents can maintain their own checkouts through the qualified Git route. No broad chmod/chown or shared-filesystem assumption is needed.

Actual r32 qualification ran as both installed Unix UIDs: GitHub account read, private fork ls-remote, real sudo, workstation SSH, and source read through the approved administrator route. Global also read the phone OS through the existing SSH hop. A login-shell smoke test retained the installed gh client and expected account. No models or product services were started for these checks, no phone input or pairing changed, and source ownership remained intact. One rejected direct source read is retained as evidence of that ownership boundary.

These are selected usable capabilities, not a complete fresh enterprise installation or a successful native build. The build entrypoint is the existing storage-build capacity guard; actual substantial builds require their own peak admission. Hollywood bootstrap, native Goal/Work/report acceptance, daily recovery and the controlled production/phone pilot remain release gates. Existing production and paused historical work remain untouched.
